# 4. RETROSPECTIVE DOCUMENTARY CHAIN — CASE-2 SEAL BOUNDARY

The retrospective path has two phases.

## 4.1 Phase A — factual baseline before semantic mapping

`PUBLIC SOURCE URL`
→ `saved snapshot / preserved source artifact`
→ `artifact identity / SHA-256 or governed content identity`
→ `EXACT EXCERPT`
→ `CERTIFIED ATOMIC FACT`
→ `Gate A / Gate B`
→ `fact scope / fact time / contradiction certification`
→ `complete BASELINE FACT PACK`
→ `canonical baseline manifest bytes`
→ `SHA-256`
→ `BASELINE EVIDENCE SEAL`.

No current-discriminator edge or Environment conclusion is authoritative before this seal.

The complete baseline manifest is content-bound under CASE-2. Fact IDs cannot conceal changed propositions, excerpts, scope, temporal eligibility, or source identity.

## 4.2 Phase B — semantic interpretation after the Evidence Seal

Only facts belonging to the exact sealed evidence-manifest version may enter:

`SEALED CERTIFIED ATOMIC FACT`
→ `DOCUMENTARY OBSERVATION`
→ `DOCUMENTARY EVIDENCE GATE`
→ `scope / temporal-continuity qualification for mapping`
→ `CURRENT DISCRIMINATOR EDGE`
→ `CASE-1 ENVIRONMENT DETERMINATION OR FAIL CLOSED`
→ `independent mapping verification`
→ `CANONICAL MERGEVUE DOWNSTREAM where lawful`
→ `canonical result artifact bytes`
→ `SHA-256`
→ `BASELINE RESULT SEAL`.

The BASELINE RESULT SEAL pins the exact BASELINE EVIDENCE SEAL ID and BASELINE EVIDENCE MANIFEST SHA-256 used.

Only after the result seal may post-T0 forensic/outcome evidence be opened.

If a new pre-T0 fact is needed after the evidence seal, CASE-2 append-only baseline versioning applies. Do not silently mutate the sealed evidence state.

# 5. DOCUMENTARY EVIDENCE GATE

This gate operates in Phase B on certified facts belonging to the exact sealed BASELINE EVIDENCE MANIFEST. It does not decide pre-seal fact membership.

A fact may enter a load-bearing documentary semantic edge only if all applicable conditions hold:

1. **Source certification** — identity, artifact/version, provenance, exact locator and reviewer status are known.
2. **Historical temporal eligibility** — for Mode C, CASE-2 Gate A and Gate B pass.
3. **Atomicity** — the fact is one inspectable proposition.
4. **Observed scope** — the organizational level actually covered is explicit.
5. **Competence** — the source is competent for the proposition.
6. **Mechanism evidence** — the fact records an actual behavior, decision mechanism, operative rule, demonstrated implementation, constitutive authority rule, or mechanically entailing event sequence.
7. **Contradiction status** — material contradictions are resolved or the edge fails closed.
8. **Semantic non-expansion** — the edge does not add motive, recurrence, scope, causality, symmetry, authority, or decision rule absent from the certified fact.
9. **Temporal relevance to T0** — when evidence is historical but substantially earlier than T0, any required continuity or later adoption bridge is explicit.
10. **Review** — governed human certification is completed by the author/reviewer, and the independent-verification obligation is discharged at the case-level verification stage before the determination is independently accepted. One batched independent case audit may discharge this condition for all load-bearing edges; no separate audit per fact is required.

Failure of any load-bearing condition prevents that edge from determining an Environment.

# 6. DOCUMENTARY EVIDENCE CLASSES

These classes describe evidence form. They are not scores.

## DE-1 — EXPLICIT BEHAVIORAL RECORD

The source explicitly records the behavior or decision mechanism.

Example shape:
formal leader preferred A; governed team process selected B; leader accepted B.

May instantiate a current discriminator if semantic, scope, and temporal tests pass.

## DE-2 — MECHANICALLY ENTAILING EVENT SEQUENCE

The source records a sequence whose causal structure establishes the mechanism even if questionnaire wording is absent.

Example shape:
prototype → real-condition test → observed defect → design changed → re-test.

The edge may support empirical iteration.

It does NOT automatically support a stronger mechanism such as:
`the test rather than hierarchy adjudicated a contested organizational decision`
unless that consequence is also established.

## DE-3 — OPERATIVE RULE + DEMONSTRATED IMPLEMENTATION

A rule is documented and real decisions/actions show that it operated.

Example shape:
measurable enterprise retention threshold → multiple actual retain/divest/withdraw decisions.

May support a performance-governance mechanism if scope and semantic-edge tests pass.

### Constitutive-rule exception

For the current authority corpus, **no known constitutive structural discriminator instance exists**.

This statement is version-bound to:

`questionnaires.json SHA-256 = b8b36cc2a9b552830882538b144be0f795f703ad0d82157f585d7c83524d4713`

and to the current accepted Environment authority set used by this contract.

If that corpus or relevant Environment authority changes, the emptiness premise must be re-established before this exception is evaluated under the new authority.

A constitutive-rule exception may be invoked only when an exact current authority anchor is positively identified and independently verified as a discriminator whose own load-bearing mechanism is formal/constitutive authority or process rather than enacted behavior inferred from structure.

Mandatory instance test:

1. name the exact current anchor: `workbook/module → question → option/current semantic`;
2. demonstrate that the anchor itself is constitutive/formal in its load-bearing mechanism;
3. demonstrate that the documentary formal fact directly entails that anchor without adding behavioral implementation;
4. independently verify the claimed constitutive status of the anchor before the edge becomes load-bearing.

If no such anchor is identified and independently verified:

`CONSTITUTIVE EXCEPTION = NOT AVAILABLE`.

The evidence remains subject to the ordinary DE-4 / non-discriminating boundary.

This exception does not bypass exact-anchor identification, semantic entailment, no-hidden-completion, scope fit, temporal relevance, or contradiction review.

If the discriminator concerns enacted behavior, rule existence alone is insufficient.

## DE-4 — STRUCTURE / ASPIRATION / POLICY-EXISTENCE ONLY

Examples:
org chart, title, board count, legal boundary, reporting line, slogan, aspirational culture language, unimplemented policy.

Default:
`NON-DISCRIMINATING` or `NOT DETERMINABLE`.

DE-4 cannot become behavioral authority merely because it resembles an Environment description.

# 7. DISCRIMINATOR INSTANTIATION TEST

The phrase `semantically equivalent` in OD-CASE3-1 is operationalized by this test.

A documentary observation instantiates a current discriminator only when all applicable conditions hold:

### 7.1 Exact current anchor

The mapping names the physical current authority:

`workbook/module → question → option / current pair semantic`.

No edge may cite only an Environment name or descriptive alias.

### 7.2 Mechanism decomposition

The current anchor and the documentary observation are compared on their load-bearing mechanism components, such as:

- trigger/context;
- authority locus;
- decision rule;
- treatment of rank/status;
- consequence;
- failure interpretation;
- test/analysis mechanism;
- enforcement mechanism.

Only components actually material to that discriminator are required.

### 7.3 Entailment, not resemblance

The certified facts must entail the load-bearing mechanism of the current anchor.

Mere correlation or visual resemblance is insufficient.

Forbidden:

`central board → NT/STJ`.

Forbidden:

`platform team → NT/STP`.

Potentially lawful:

`measurable enterprise rule + demonstrated consequences → performance-governance discriminator candidate`.

Potentially lawful:

`prototype/test/feedback sequence → empirical-iteration discriminator candidate`.

### 7.4 No hidden completion

No analyst may supply a missing element because it would make the classification coherent.

If the current anchor requires:
`test result decides the contested issue`
and the document proves only:
`test exposed a defect and engineers fixed it`,
the stronger edge is not established.

### 7.5 Directionality

The observation must support the same semantic direction as the anchor.

If it supports multiple options or remains compatible with materially different mechanisms, classify it as SHARED / NON-DISCRIMINATING / NOT DETERMINABLE as appropriate.

### 7.6 Scope and time

The same mechanism must be supported at the claimed organizational scope and relevant T0 state under §§9–10.

### 7.7 Contradiction

A materially contrary certified observation blocks or qualifies the edge according to existing CASE-1 contradiction rules.

# 8. OPERATIVE RULE TEST

An `operative rule` is not merely a written policy.

For a behavioral discriminator, the rule is operative only when:

1. the rule was in force at the relevant organizational scope and analysis time; AND
2. certified evidence shows that the rule governed at least one actual decision/action, or that a competent contemporaneous source explicitly records its routine application.

No universal event count applies.

A single authoritative record may establish repeated/routine application if the record itself actually says so.

For a constitutive formal-authority/process discriminator, formal legal/governance force may itself be the relevant mechanism.

---

# 9. REPEATED PRACTICE TEST

`Repeated practice` is mechanism-based, not count-based.

It requires evidence that the behavior was recurrent, routine, institutionalized, or characteristically applied at the claimed scope.

It may be established by:

- one competent source that explicitly records recurring/routine practice;
- a documented institutional process plus implementation;
- multiple actual episodes whose common mechanism is inspectable;
- a later pre-T0 institutionalization/adoption record that lawfully bridges earlier program practice to the claimed scope.

It is NOT established merely because:

- two similar anecdotes exist;
- one team repeats an action;
- one source uses plural language without scope;
- a pilot was intended as a model;
- a practice was aspirational;
- the source itself calls the conduct exceptional.

No fixed minimum number is introduced.

---

# 10. ORGANIZATIONAL SCOPE / GENERALIZATION BRIDGE

Every edge records:

`OBSERVED SCOPE`
and
`CLAIMED MAPPING SCOPE`.

Canonical descriptive levels for research:

`individual → team → program → unit/division → enterprise`.

These are descriptive research levels, not new runtime types.

Upward generalization requires an explicit bridge.

A lawful bridge may include:

- an enterprise rule shown to operate across the relevant portfolio;
- documented adoption of the same mechanism across relevant units/programs;
- a contemporaneous enterprise-wide standard plus evidence of implementation;
- repeated multi-unit evidence whose common mechanism and scope are explicit;
- another inspectable institutional mechanism that logically governs the claimed level.

Unlawful bridge:

`one successful team → whole company`.

Unlawful bridge:

`platform-team structure became standard → every behavioral mechanism observed in the original pilot became enterprise practice`.

If a source says a practice was exceptional, resisted, transitional, protected, experimental, or not yet adopted broadly, that statement is adverse scope evidence and must be retained.

If scope bridge remains unresolved:
`FAIL CLOSED AT CLAIMED SCOPE`.

---

# 11. TEMPORAL RELEVANCE / CONTINUITY TO T0

CASE-2 Gate A answers:
did the fact/mechanism exist by T0?

Gate B answers:
was it publicly knowable by T0?

For an Environment determination, an older episode must additionally be probative of the organizational state being assigned at T0.

No universal recency threshold is introduced.

A continuity bridge is required when:

- the evidence is materially remote from T0;
- the source itself describes transition or experimentation;
- relevant leadership/organization materially changed;
- later pre-T0 evidence suggests a different mechanism;
- scope generalization depends on adoption over time.

Continuity may be established by:

- later pre-T0 repetition;
- later pre-T0 institutionalization;
- contemporaneous source explicitly stating continued practice;
- a still-operative rule whose application is demonstrated;
- another lawful bridge showing persistence.

Old evidence is not rejected merely because it is old.

But old exceptional program evidence cannot silently become T0 enterprise behavior.

---

# 12. INTERESTED SELF-DESCRIPTION

Interested self-description may establish:

`the actor/company publicly stated X`.

It does not automatically establish:
`X accurately characterizes organizational behavior`.

If a load-bearing behavioral edge depends on interested self-description, apply CASE-2 corroboration law.

Independent corroboration is required where the self-description is being used to establish actual behavior, scope, recurrence, or consequence.

A self-adverse admission may be probative, but its factual comparison still requires the same contradiction/corroboration discipline.

# 13. MAPPING PACKAGE / EDGE RECORD

Every retrospective mapping act is bound to one exact sealed evidence state.

## 13.1 Required mapping-package input binding

The mapping package must record:

- Case ID
- BASELINE EVIDENCE SEAL ID
- BASELINE EVIDENCE MANIFEST SHA-256
- baseline manifest version
- mapping package version
- mapping package creation time
- mapping author
- questionnaire authority SHA-256
- current Environment authority identity.

The evidence seal ID and manifest digest are immutable inputs to that mapping-package version.

If the evidence baseline changes, create a new mapping-package version and re-run affected edges.

## 13.2 Required load-bearing edge record

Every load-bearing retrospective edge must record at minimum:

- Edge ID
- Case ID
- Side
- Fact ID(s)
- Source ID(s)
- source artifact digest
- source identity class
- BASELINE EVIDENCE SEAL ID
- BASELINE EVIDENCE MANIFEST SHA-256
- exact excerpt / locator
- publication/public-availability date
- fact/event/effective date
- observed organizational scope
- claimed mapping scope
- scope-bridge basis or `NONE / UNRESOLVED`
- temporal-continuity basis or `NOT_REQUIRED / UNRESOLVED`
- DE class
- exact current discriminator anchor
- discriminator mechanism decomposition
- support class
- unique/shared status
- contradiction status
- interested-self-description status
- reviewer status
- independent-verification status.

Allowed source identity classifications for research traceability:

- `BYTE_IDENTITY`
- `CONTENT_IDENTITY`
- `IDENTITY_ONLY`
- `CONTENT_INACCESSIBLE`.

These are research labels, not runtime enums.

## 13.3 Sealed-fact membership invariant

A load-bearing edge is valid only if:

1. its Fact ID exists in the exact manifest identified by `BASELINE EVIDENCE MANIFEST SHA-256`;
2. the proposition used by the edge matches the certified fact content in that exact manifest version;
3. the edge-level Evidence Seal ID and manifest digest match the mapping-package input binding;
4. source artifact identity/digest matches the source identity carried by the sealed baseline where technically applicable.

A correct fact that is absent from the sealed manifest is unavailable to that mapping version.

If required sealed-fact membership cannot be established:

`SEALED_FACT_MEMBERSHIP_FAILURE`.

This is a research/governance fail-closed label, not a runtime enum.

No Environment determination may rely on an edge whose load-bearing record has an unresolved required field or failed sealed-fact membership invariant.

# 16. INDEPENDENT VERIFICATION RULE

Every load-bearing mapping edge must be independently verifiable.

This does NOT require one separate audit per edge.

One independent case-level audit may batch all load-bearing edges, but before accepting the mapping it must independently verify the mapping-package evidence binding:

- BASELINE EVIDENCE SEAL ID;
- BASELINE EVIDENCE MANIFEST SHA-256;
- exact sealed manifest bytes or authenticated preserved manifest artifact;
- mapping-package version.

For each load-bearing edge it must independently:

- confirm that the Fact ID exists in that exact sealed manifest;
- confirm that the proposition used by the edge matches the certified fact content in that exact manifest version;
- confirm that the edge-level Evidence Seal ID and manifest digest match the mapping-package binding;
- re-retrieve the public source from the canonical locator, or retrieve the preserved authenticated snapshot/original when live retrieval is unavailable;
- establish content identity / byte identity to the extent technically available;
- verify the source artifact digest and source identity class against the sealed baseline record where technically available;
- inspect the exact source locator and excerpt;
- confirm the atomic fact content;
- check DE class;
- check the current discriminator anchor;
- re-test semantic instantiation;
- check observed/claimed scope;
- check scope bridge;
- check temporal continuity;
- check contradiction status;
- check support class.

A URL existence check, the author's edge table, the author's own source excerpt, or familiarity with the Fact ID is not by itself independent verification.

A fact can be true and independently source-valid yet still be unavailable to a mapping version if it is absent from that exact sealed manifest.

If neither the public source nor a preserved authenticated artifact can be independently inspected, a load-bearing edge remains `DOCUMENT_CONTENT_INACCESSIBLE`.

The verifier must be a different actor from the mapping author for the audited act.

A final Environment PASS cannot be based only on the author's edge table.

Before accepting the BASELINE RESULT SEAL, the verifier must also confirm:

`result.baselineEvidenceSealId == acceptedMappingPackage.baselineEvidenceSealId`

and

`result.baselineEvidenceManifestSha256 == acceptedMappingPackage.baselineEvidenceManifestSha256`.

A mismatch fails closed as:

`RESULT_EVIDENCE_DIGEST_MISMATCH`.

This is a research/governance fail-closed label, not a runtime enum.

# 19. REUSABLE RETROSPECTIVE CASE PROTOCOL V1 — CANDIDATE

After this contract passes independent verification and Owner acceptance, the intended reusable sequence for each remaining case is:

1. **T0 + firstness determination**
2. **public source acquisition / preservation**
3. **source certification**
4. **atomic fact extraction**
5. **Gate A / Gate B + factual scope/date/contradiction certification**
6. **independent source/fact verification as required for seal-ready facts**
7. **complete canonical BASELINE FACT PACK / baseline manifest**
8. **BASELINE EVIDENCE SEAL**
9. **Documentary Observation + Documentary Evidence Gate**
10. **mapping-scope + temporal-continuity qualification**
11. **mapping package bound to exact Evidence Seal ID / manifest digest + question-level current discriminator edges**
12. **CASE-1 confusion / contradiction / thin-coverage determination**
13. **independent mapping verification**
14. **canonical downstream: lawful pair → ECS/resources/friction/verified narrative**
15. **BASELINE RESULT SEAL**, pinning the exact evidence-manifest digest
16. only then **post-T0 forensic / outcome verification**.

The BASELINE EVIDENCE SEAL is a hard procedural anti-hindsight boundary.

No current-discriminator mapping result may determine which facts belong in the already sealed baseline.

If mapping reveals a need for additional pre-T0 evidence, create a superseding append-only baseline version under CASE-2, produce a new evidence digest, and re-run affected mapping. Do not silently add the fact to the prior baseline.

For efficiency, Phase-A evidence preparation may be combined into one author act only when all source/fact/Gate/manifest surfaces remain separately inspectable. Phase-B semantic mapping may also be combined into one author act when all mapping-edge surfaces remain separately inspectable.

Phase A and Phase B must **not** be compressed across the BASELINE EVIDENCE SEAL.

The independent audit remains fully independent and must re-retrieve and check every load-bearing source/edge under §16.

Compression is not justified merely because the protocol is familiar. Where the authoring process or case evidence has not demonstrated low-defect execution, explicit stage separation is preferred over speed.

No fixed number of post-pilot cases and no mandatory correction round is introduced.

Corrections occur only for real defects, not as ceremonial mandatory rounds.
