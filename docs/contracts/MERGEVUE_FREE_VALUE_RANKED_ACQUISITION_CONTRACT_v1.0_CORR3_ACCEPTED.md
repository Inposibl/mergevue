## §0. PURPOSE AND HUMAN CLAIM

This contract governs one thing: the lawful order, execution, and stopping of
public-document acquisition for the MergeVue FREE lane.

HUMAN CLAIM: Given an unresolved model data need, this contract determines
which public-document acquisition step is lawfully activated next, how it is
executed for both Acquirer and Target, when another rung is activated, when
collection stops, and how the resulting evidence envelope is represented
without pretending that unreviewed public evidence was searched.

This contract creates NO new Environment semantics, NO new discriminators, NO
support weights, NO evidence weights, NO confidence scores, NO synthetic
coverage scores, NO ECS mathematics, NO analytical conclusions, and NO new
proposition/result states (§11.3).

## §2. TWO-LAYER ARCHITECTURE

### §2.1 LAYER A — COMMON MANDATORY DISCOVERY ENVELOPE
Executed for every side of every FREE analysis. It is MINIMAL by design:

- canonical filer identity (Mode-D P1 where the factual lane is active);
- issuer submissions / filing-class history needed for the current lawful
  factual lane;
- accession/date metadata (filingDate, reportDate, evidence-cutoff fields);
- the minimal provenance/discovery metadata already required by Mode-D
  (§8.3 locator/artifact-identity obligations).

Its competent surface is D1 (§2.3).

**Boundary (load-bearing):** the common envelope is NOT "search all competent
discovery surfaces." Layer A contains no exhibit enumeration and no
third-party discovery. Those are need-activated services (§2.2) and execute
only because a lawfully ACTIVE rung requires them.

Layer A is infrastructure and, solely for the factual lane, an authorized
evidence source. It is NOT the analytical evidence base of any future
mechanism lane. For mechanism-level evidence, retrieved documents and
exhibits are the evidence sources (Layer B, §2.6).

### §2.2 NEED-ACTIVATED DISCOVERY SERVICES
The following execute ONLY because a lawfully ACTIVE rung (§5) requires them
for a declared proposition need — NEVER merely because a FREE analysis
started:

- D2 filing-container / exhibit enumeration (§2.4);
- D3 third-party / subject-company discovery (§2.5);
- any other class-specific discovery surface a rung declares.

Each service inherits the activating rung's declared bound, temporal rule,
side scope, and reference-data identities. A service executed without an
activating ACTIVE rung is a contract violation.

### §2.3 DISCOVERY SURFACE D1 — FILER / SUBMISSIONS DISCOVERY
(common-envelope surface; part of §2.1)
Competent for: canonical issuer identity; the issuer-filed form/accession
history; filingDate/reportDate; issuer-level filing-class discovery where and
only where the source actually publishes it.
Competence basis: the structured issuer submissions index, as verified
against live EDGAR mechanics (submissions JSON: forms, accessions, dates,
items where published).
NOT competent for: records filed by other filers concerning the company
(§2.5) without a dedicated competent lookup; exhibit membership inside an
accession (§2.4).

### §2.4 DISCOVERY SURFACE D2 — FILING-CONTAINER / FILING-INDEX DISCOVERY
(need-activated service under §2.2)
Competent for: members/documents inside one identified accession; exhibit
enumeration; exhibit type / filename / sequence where lawfully available.
Competence basis: the accession's own filing container/index surfaces,
verified mechanically (filing index listings enumerate members; identity of
member type is established by the container's own descriptors, never
inferred from the parent filing's existence).
NOT competent for: issuer identity; cross-filer discovery.

### §2.5 DISCOVERY SURFACE D3 — THIRD-PARTY / SUBJECT-COMPANY DISCOVERY
(need-activated service under §2.2)
Competent for: classes filed by another filer but concerning the subject
company — including SC 13D / SC 13G and equivalent holder-filed records.

**D3 competence rule (positive binding required).** A D3 mechanism is
competent ONLY IF it positively binds, for each located record:

    third-party filing
    → exact subject company
    → exact form/accession
    → declared temporal bound.

A text mention alone is insufficient. A generic full-text hit alone is
insufficient unless the discovery mechanism proves the subject-company
relation required by the rung. No particular SEC search interface is
controlling merely because a bounded probe happened to locate a filing
through one: this contract defines the D3 competence REQUIREMENTS; a later
implementation act proves the actual D3 adapter against them.

NOT competent for: issuer identity; exhibit membership.

### §2.6 LAYER B — VALUE-RANKED ANALYTICAL DOCUMENT ACQUISITION
Need-activated acquisition rungs (§3) over document classes and exhibit scopes
(§4–§5), executed rung-symmetrically (§6), recorded per side (§7), stopped by
§8, and disclosed through the envelope (§15).

## §3. MODEL-NEED ACTIVATION

No document class may activate merely because it exists, is cheap, is
structured, or is reachable.

Every acquisition rung must be activated by the chain:

    UNRESOLVED MODEL NEED
    → EXACT PROPOSITION NEED
    → MECHANISM / DISCRIMINATOR FAMILY (as defined by controlling methodology)
    → COMPETENT DOCUMENT CLASS (competence is SOURCE × PROPOSITION)
    → COMPETENT DISCOVERY CHAIN for that class (§2.3–§2.5; §3.1)
    → DECLARED ACQUISITION RUNG.

## §5. LADDER CONSTRUCTION AND LADDER LIFECYCLE

Architecture: **HYBRID — COMMON ENVELOPE BASE + DISCRIMINATOR-SPECIFIC
LADDERS.** The base is Layer A (§2.1): identity, discovery, temporal fields,
factual-lane propositions. It is not a value ranking. Expansion is organized
into discriminator-specific ladders. No universal list ("8-K > DEF 14A >
10-K > …") is defined, because competence is proposition-specific.

### §5.1 Ladder register schema

    ladderId
    discriminatorFamily
    rungs[]                 rung declarations (§3.1), in declared order
    orderingAuthorityBasis  METHODOLOGY_ESTABLISHED | EMPIRICALLY_ESTABLISHED |
                            OWNER_ESTABLISHED   (§5.2 rule; required for ACTIVE)
    lifecycleStatus         HYPOTHESIS | ACTIVE
    predeclaredAt           instant of declaration
    evidenceBasis           for EMPIRICALLY_ESTABLISHED: the bounded probe act
                            and scope that established THIS ladder's order

### §5.2 ACTIVE-LADDER AUTHORITY RULE (load-bearing)

A document-class order may become an ACTIVE value-ranked ladder only when the
order is supported by:

    A. current controlling methodology/authority; or
    B. bounded empirical evidence sufficient for that discriminator-specific
       comparison; or
    C. an explicit Owner decision where the ordering is normative.

Predeclaration alone does NOT establish value. Its purpose is only to prevent
post-hoc tuning after an order has otherwise been lawfully established.

### §5.3 Ladder lifecycle

    DISCOVERED NEED
    → CANDIDATE COMPETENT CLASSES (via §4 + methodology competence rules)
    → ORDERING AUTHORITY CHECK (§5.2 A/B/C)
    →
        ORDER ESTABLISHED (A, B, or C satisfied for that order)
            → ladder may be declared ACTIVE (rungs executable)
        ORDER NOT DETERMINABLE / NEEDS VALUE PROBE
            → ladder remains HYPOTHESIS; activation requires a bounded value
              probe act whose result, if sufficient for this comparison,
              supplies basis B; or an Owner decision (basis C)
        OWNER DECISION REQUIRED
            → the ordering question is returned through the Owner Decision
              Frame; on acceptance the ladder may become ACTIVE with basis C

An unsupported provisional ordering may be stored as a research hypothesis
(lifecycleStatus = HYPOTHESIS). It may NOT be executed merely because it was
predeclared. No runtime LLM and no runtime model of any kind may choose among
NOT-DETERMINABLE classes: class priority is resolved only by A, B, or C.

## §6. RUNG-SYMMETRIC EXECUTION (load-bearing)

For each activated rung (of an ACTIVE ladder):
- execute the same rung definition for Acquirer;
- execute the same rung definition for Target;
- use the same document-class rule;
- use the same temporal rule;
- use the same exhibit/section scope rule;
- use the same reference-data version (C1 identities recorded per side);
- preserve per-side result states.

The resulting evidence NEED NOT be equal. The resulting document count NEED
NOT be equal. The resulting evidence quality NEED NOT be equal.

**Symmetric execution means symmetric protocol, NOT fabricated evidentiary
symmetry.** Per-side availability differences (a class or exhibit scope that
exists for one side only) are recorded through §11 metadata — they do not
break protocol symmetry, and they are never repaired by substituting unequal
collections.

This section implements Owner Decision B and is consistent with Mode-D
symmetric-execution lineage (each executed rung is a declared bound with
identical record-class rules and reference-data identities across sides,
per Mode-D §25.2 symmetryRule).

## §7. PER-SIDE SUFFICIENCY

Sufficiency is evaluated independently per side after every completed rung,
and recorded as:

    ACQUIRER:
      sufficiencyState         per the active lane's lawful semantics (§9)
      unresolvedRequiredNeeds  declared needs still not satisfied
      contradictions           open CONFLICT_CANDIDATE states at matched
                               scope/time (Mode-D §14)
      materialAlternativeState surviving alternatives where methodology
                               requires their handling
      coverageLimitation       coverage state + disclosed limitations
                               (Mode-D §16)

    TARGET: the same fields, independently.

Do not average sides. Do not let strong evidence on one side cure weak
evidence on the other. Strong evidence on one side must not mask weak evidence
on the other (RPA §17.2 obligation at projection; enforced upstream here by
never aggregating sufficiency).

## §8. NEXT-RUNG RULE

After each completed rung (of an ACTIVE ladder):

    IF both sides meet the predefined lawful sufficiency condition for the
       active lane:
           STOP. (ladderExecutionStatus = STOPPED_BOTH_SUFFICIENT)

    ELSE IF at least one side remains insufficient AND an authorized competent
       next rung exists in the ACTIVE ladder:
           execute that next rung for BOTH sides (§6), then re-evaluate.

    ELSE:
           terminate (ladderExecutionStatus = LADDER_EXHAUSTED), preserving
           all per-side unresolved states.

`ladderExecutionStatus` is CONTROL-PLANE ACQUISITION METADATA (§11.3). It is
not a client-facing analytical state. The user-facing result is mapped only
through existing insufficiency semantics (e.g., contract 19 §87 availability
states and Mode-D result states). No new client-facing state is created for
acquisition convenience.

Collection never continues past STOP merely because more documents exist, and
never continues below an exhausted ladder merely because evidence might
hypothetically exist.

    COLLECTION COMPLETENESS  ≠  EVIDENCE SUFFICIENCY  ≠  ANALYTICAL DETERMINACY

## §10. COUNTEREVIDENCE CONTROL (minimum, methodology-grounded)

1. Interested self-description cannot close a behavioral discriminator by
   itself where corroboration is required (CASE-3.4 §12); the ladder must
   declare the corroborating rung and it must execute before STOP.
2. Mandatory counterevidence-capable sources/rungs defined by the ladder must
   be executed before STOP.
3. An unresolved material contradiction (CONFLICT_CANDIDATE at matched scope
   and time) blocks sufficiency for the affected need.
4. The strongest material alternative must be handled before lawful STOP
   where current methodology requires it (downstream enforcement: RPA §18.6).
5. Rung order must be fixed before the desired conclusion is known — and,
   per §5.2, lawfully established before it is executable (predeclaration
   alone prevents tuning; it does not create value; no outcome tuning).

These controls never require exhaustive EDGAR collection. Beyond the declared
ladder, lower-ranked sources are not consulted merely because they might
hypothetically change the result (guardrail §12).

## §11. CONDITIONAL DOCUMENT CLASSES — METADATA STATES

### §11.1 Exceptional acquisition semantics
Four distinct exceptional acquisition semantics require explicit non-collapse
treatment for conditional or incomplete collection situations (conditional
classes; unavailable sources; searched-and-not-found; unreviewed remainder).
They are exceptional cases INSIDE the larger closed acquisition-metadata model
of §§11.2–11.3; they do not exhaust that model, and no enum is defined in
this subsection — the complete operational state inventory is §11.3. In
particular, `NOT_EXECUTED` and `FOUND_WITHIN_EXECUTED_BOUND` (§11.3) remain
fully valid for conditional classes: a conditional rung that never activates
leaves its class NOT_EXECUTED, and a conditional class searched and located is
FOUND_WITHIN_EXECUTED_BOUND. Unless an existing methodology state is expressly
invoked, the semantics below are acquisition/control-plane metadata:

    (i)  NOT APPLICABLE BY PREDECLARED CONDITION
         RESERVED for a condition established INDEPENDENTLY of executing the
         search for the target record — for example: a transaction-specific
         filing class whose governing transaction condition lies outside the
         active scenario; a class whose applicability predicate is false
         BEFORE the target search is executed.
         Metadata: acquisitionApplicability =
         NOT_APPLICABLE_BY_PREDECLARED_CONDITION.
         It MUST NOT be used merely because a competent search or enumeration
         ran and returned no target record — that situation belongs to (ii)
         or (iii). It is NOT a search result. It is NOT negative evidence
         about the companies.

    (ii) NOT FOUND WITHIN EXECUTED BOUND
         The class was in scope, the bound executed for the side, and no
         qualifying record was established. Metadata:
         recordSearchState = NOT_FOUND_WITHIN_EXECUTED_BOUND. Where a
         proposition-level representation is required, the EXISTING Mode-D
         state (NOT_ESTABLISHED_WITHIN_BOUND, with §16.4.1 Situation-1
         rendering) governs. No absence claim.

    (iii) SOURCE UNAVAILABLE
         The competent source could not be retrieved for the side. Metadata:
         recordSearchState = SOURCE_UNAVAILABLE. Where proposition-level
         representation is required, Mode-D §16.4.1 Situation-2 obligations
         apply (no copy implying examination; foregrounding). No negative
         evidence.

    (iv) UNREVIEWED REMAINDER
         Lower-ranked or unexecuted classes not consulted because lawful STOP
         or LADDER_EXHAUSTED occurred first. Metadata:
         remainderReviewStatus = UNREVIEWED. Creates no result state at all
         and no negative evidence.

### §11.2 Exhibit-enumeration state machine
For EX-10 / EX-21 / EX-2.1 / EX-99 and any other exhibit scope, exactly one
metadata state applies, determined solely by the D2 service (§2.4):

    D2 NOT EXECUTED (no ACTIVE rung requires it)
        → recordSearchState = NOT_EXECUTED
    D2 CANNOT EXECUTE (rung active; enumeration cannot be performed)
        → recordSearchState = SOURCE_UNAVAILABLE
    D2 EXECUTED + TARGET FOUND
        → recordSearchState = FOUND_WITHIN_EXECUTED_BOUND
    D2 EXECUTED + TARGET NOT FOUND
        → recordSearchState = NOT_FOUND_WITHIN_EXECUTED_BOUND

No row of this machine may be replaced by
NOT_APPLICABLE_BY_PREDECLARED_CONDITION: exhibit presence or absence is
established only by executing or failing to execute the competent D2
enumeration, never by a pre-search predicate. No universal absence claim
follows from any row.
