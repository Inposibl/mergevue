**Статус документа:** мастер-документ пользовательского пути  
**Назначение:** зафиксировать последовательность взаимодействия пользователя с MergeVue от первого контакта до последующей проверки прогнозов  
**Область действия:** публичный сайт, методология, исторические кейсы, публичный анализ сделки, регистрация, рабочее пространство, платные уровни, корпоративное согласование, 42Q, отчёты, последующая проверка  
**Версия:** 1.0  
**Дата:** 15 сентября 2026 года  
**Связанные документы:** `00_MERGEVUE_DESIGN_PROGRAM_OVERVIEW_v1.1.md`, `01_MERGEVUE_PRODUCT_NORTH_STAR.md`, `02_MERGEVUE_AUDIENCES_BUYERS_AND_ROLES.md`

# 0. Назначение документа

Этот документ описывает не отдельные страницы, а движение пользователя через всю систему MergeVue.

Для каждого этапа необходимо понимать:

- кто находится в системе;
- что он уже знает;
- чего он ещё не знает;
- какую ценность он уже получил;
- что мешает ему двигаться дальше;
- какое действие является естественным следующим шагом;
- какие данные система уже имеет право использовать;
- какие данные ещё нельзя запрашивать;
- что должно произойти за интерфейсом;
- какой уровень доверия требуется для перехода дальше.

Главный принцип:

> пользователь должен получать новую ценность раньше, чем система просит у него новую степень доверия.

---

# 1. Общая схема пути

Полный путь MergeVue состоит из девяти фаз:

1. понимание проблемы;
2. проверка серьёзности метода;
3. проверка на собственной сделке;
4. переход к собственным данным;
5. углублённая проверка;
6. корпоративное согласование;
7. платный анализ;
8. выпуск прогноза;
9. последующая проверка.

---

# 2. Сквозная лестница доверия

Пользователь последовательно:

1. ничего не передаёт;
2. читает публичную информацию;
3. смотрит исторические кейсы;
4. вводит только названия компаний;
5. получает публичный результат;
6. создаёт учётную запись;
7. добавляет собственные наблюдения;
8. приглашает респондентов;
9. принимает решение передать закрытые документы;
10. проходит корпоративное согласование;
11. при необходимости приглашает руководителей к 42Q;
12. получает платный прогноз;
13. возвращается для последующей проверки.

Каждая следующая ступень требует большего доверия и должна давать больший уровень ценности.

---

# 3. Первый вход на сайт

## Главный вопрос

> «Что MergeVue может показать такого, чего я не получаю из обычной проверки сделки?»

## Что должна объяснить главная

- MergeVue анализирует организационный риск сделки;
- система ищет уязвимые предположения инвестиционного тезиса;
- результатом является проверяемый прогноз;
- продукт можно попробовать без регистрации.

## Главное действие

Запустить анализ собственной сделки.

## Альтернативные действия

- посмотреть исторические кейсы;
- изучить методологию;
- изучить девять сред;
- перейти к платным возможностям.

## Что нельзя требовать

- регистрацию;
- корпоративную почту;
- номер телефона;
- анкету;
- закрытые документы;
- согласование покупки.

---

# 4. Проверка серьёзности метода

Публично доступны:

- «Как работает MergeVue»;
- методология;
- девять сред взаимодействия;
- модель ресурсов;
- логика прогнозирования;
- проверяемость;
- исторические кейсы;
- ограничения метода.

Главный вопрос пользователя:

> «Есть ли за продуктом реальная модель, или это просто автоматически сгенерированный текст?»

Пользователь должен понять:

- девять сред происходят из авторской теории;
- система работает с доказательствами;
- доказательства имеют разную силу;
- противоречия не скрываются;
- математическая логика отделена от теории;
- прогноз должен быть проверяемым;
- исторические кейсы используют предсобытийную отсечку;
- у метода есть ограничения.

Следующий естественный шаг — проверить метод на конкретной сделке.

---

# 5. Начало публичного анализа сделки

Минимальный вход:

- компания-покупатель;
- целевая компания.

Дополнительно:

- тип сделки;
- краткая цель;
- текущая стадия;
- смысл приобретения.

Система должна сначала использовать то, что может найти сама.

---

# 6. Подтверждение компаний

После ввода названий система подтверждает правильность сущностей.

Пользователь видит:

- название;
- страну;
- отрасль;
- при необходимости материнскую структуру;
- краткий идентификатор.

Возможные состояния:

- обе компании найдены;
- одна компания неоднозначна;
- обе компании неоднозначны;
- компания не найдена;
- найдено несколько одноимённых организаций.

Анализ не начинается, пока сущности не разрешены достаточно надёжно.

---

# 7. Контекст сделки

Система задаёт только вопросы, которые существенно меняют анализ.

Например:

- приобретается команда;
- приобретается технология;
- приобретается рынок;
- приобретается клиентская база;
- планируется полная интеграция;
- планируется сохранение автономии;
- цель связана с синергией;
- цель связана с устранением конкурента.

Каждый вопрос должен иметь понятное влияние на дальнейший анализ.

---

# 8. Исследование по открытым данным

Пользователь видит реальные стадии:

1. подтверждение участников сделки;
2. сбор открытых источников;
3. проверка временной допустимости;
4. выделение существенных фактов;
5. поиск противоречий;
6. структурная интерпретация;
7. формирование рисков;
8. построение проверяемых гипотез.

Не требуется раскрывать внутренние цепочки рассуждений, служебные коды и технические операции.

---

# 9. Публичный результат

Это первая крупная точка создания ценности.

Пользователь получает:

- три–пять основных зон проверки;
- объяснение механизма;
- публичные доказательства;
- противоречия;
- существенные неизвестные;
- вопросы для дальнейшей проверки;
- временные окна;
- наблюдаемые признаки;
- условия опровержения.

Временные окна:

- первые 30 дней;
- примерно 30–60 дней;
- примерно 2–6 месяцев;
- примерно 6–18 месяцев.

На этом уровне не обещаются:

- окончательное определение среды;
- персональный прогноз руководителя;
- анализ закрытых документов;
- глубокая экономическая экспозиция;
- гарантированный результат;
- решение «покупать / не покупать».

---

# 10. Переход после публичного результата

Ключевая формулировка:

> «У вас могут быть данные, которых нет в открытых источниках».

Следующий шаг:

> «Добавьте то, что известно вам».

Это естественная точка регистрации.

---

# 11. Регистрация

Причина регистрации:

- сохранить сделку;
- продолжить анализ;
- добавить собственные наблюдения;
- пригласить респондентов;
- вернуться позже;
- получить обновлённый результат.

После регистрации публичный анализ автоматически становится частью рабочего пространства сделки.

---

# 12. Рабочее пространство сделки

Открывается уже заполненным тем, что система знает.

Основные разделы:

- обзор сделки;
- тезис сделки;
- открытые доказательства;
- собственные наблюдения;
- опросы;
- противоречия;
- текущие риски;
- прогнозы;
- недостающие данные;
- платные возможности;
- участники.

---

# 13. Добавление собственных наблюдений

Каждое наблюдение получает контекст качества:

- видел лично;
- подтверждено документом;
- известно со слов другого человека;
- вывод;
- предположение;
- неизвестно.

Пользователь не должен иметь возможность незаметно превратить предположение в факт.

---

# 14. Организационные опросы

Опросы углубляют уже существующий анализ.

Пользователь понимает:

- зачем нужен опрос;
- что он изменит;
- кто должен отвечать;
- сколько времени это займёт.

После ответов показывается изменение анализа:

- гипотеза усилилась;
- ослабла;
- возникло противоречие;
- данных по-прежнему недостаточно.

---

# 15. Приглашение респондентов

Респондент получает отдельный ограниченный путь:

1. приглашение;
2. кто пригласил;
3. зачем нужны ответы;
4. правила данных;
5. вопросы;
6. завершение.

Респондент не должен автоматически видеть всё рабочее пространство.

---

# 16. Обновлённый бесплатный анализ

Система показывает:

> публичная гипотеза → внутренние данные → новое состояние.

Возможные состояния:

- подтверждено;
- опровергнуто;
- не разрешено;
- противоречие;
- неизвестно.

Это вторая крупная точка создания ценности.

---

# 17. Переход к платному уровню

Платный переход возникает как ответ на ограничение бесплатного анализа.

Причины:

- ключевой вопрос нельзя решить без закрытых документов;
- экономическая зависимость сделки существенна;
- требуется глубокая проверка нескольких зависимостей;
- нужен прогноз по конкретным руководителям;
- нужен материал для инвестиционного комитета;
- требуется зафиксированный прогноз с усиленной проверкой.

---

# 18. Определение экономической экспозиции

Перед дорогим анализом система помогает сформулировать:

1. тезис сделки;
2. зависимость создания стоимости;
3. организационное предположение;
4. возможный механизм нарушения;
5. ориентир стоимости, подверженной риску.

Цена должна восприниматься как стоимость проверки существенного вопроса, а не как цена за количество страниц.

---

# 19. Выбор уровня анализа

## Бесплатный

Что видно по открытым данным.

## 5 000 долларов

Подтверждается ли публичная гипотеза закрытыми материалами.

## 10 000 долларов

Какая часть экономической логики сделки уязвима.

## 15 000 долларов

Какие несколько ключевых зависимостей требуют глубокой проверки.

## 30 000 долларов

Как выглядит решение уровня инвестиционного комитета по материальному организационному риску.

Не следует показывать уровни как обычные тарифные карточки подписки.

---

# 20. Корпоративное согласование

Для дорогого анализа возможны четыре параллельных контура.

## Юридическая проверка

- договор;
- режим данных;
- права сторон;
- хранение и удаление.

## Информационная безопасность

- хранение;
- доступ;
- внешние поставщики;
- журналирование;
- человеческий доступ;
- удаление.

## Закупки

- юридические данные;
- описание услуги;
- стоимость;
- срок;
- реквизиты;
- документы поставщика.

## Финансы

- счёт;
- сумма;
- валюта;
- основание;
- подтверждение оплаты.

Прогресс пользователя не должен теряться во время согласования.

---

# 21. Открытие платного рабочего пространства

После оплаты платный уровень становится продолжением той же сделки.

Добавляются:

- закрытые материалы;
- более глубокий анализ;
- экономическая экспозиция;
- дополнительные прогнозные линии;
- индивидуальный анализ руководителей;
- усиленная проверка качества.

---

# 22. Загрузка закрытых материалов

До первой загрузки пользователь подтверждает:

- право предоставить материал;
- понимание режима обработки;
- понимание правил доступа;
- понимание правил хранения и удаления.

Каждый файл имеет:

- название;
- категорию;
- дату;
- источник;
- статус обработки;
- уровень доступа;
- связь с выводами.

Состояния:

- загружен;
- обрабатывается;
- обработан;
- требует проверки;
- недопустим;
- противоречит другим данным;
- удалён.

---

# 23. Углублённый анализ

Система объединяет:

- открытые данные;
- закрытые материалы;
- наблюдения;
- ответы;
- организационные сигналы;
- ресурсную модель;
- экономическую экспозицию.

Пользователь видит:

- какие выводы изменились;
- почему;
- какие вопросы остались;
- что теперь наиболее существенно.

---

# 24. Решение о персональном прогнозе

Если клиент хочет понять поведение конкретных руководителей, появляется отдельный путь:

> «Добавить индивидуальный прогноз ключевых руководителей».

Система объясняет:

- зачем это нужно;
- почему общего организационного анализа недостаточно;
- что потребуется 42Q;
- что внутренний тип не будет опубликован;
- что клиент получит поведенческий прогноз.

---

# 25. Выбор руководителей для 42Q

Выбираются только руководители, чьё поведение существенно для сделки.

Для каждого фиксируются:

- имя;
- роль;
- организация;
- значение роли;
- почему человек критичен;
- какую зависимость сделки он поддерживает.

42Q не должен превращаться в массовое тестирование сотрудников.

---

# 26. Приглашение к 42Q

Участник получает отдельное приглашение с объяснением:

- кто запрашивает участие;
- зачем;
- сколько времени;
- какие данные собираются;
- как они будут использоваться;
- что внутренний тип не будет выдан как результат теста;
- куда обращаться по вопросам данных.

---

# 27. Прохождение 42Q

Интерфейс должен быть нейтральным.

Необходимо минимизировать:

- влияние контекста сделки;
- социально желаемые ответы;
- подсказки о «правильных» вариантах.

Пользователь видит:

- прогресс;
- понятные инструкции;
- возможность продолжить;
- состояние завершения.

---

# 28. Внутренняя обработка 42Q

Не является клиентским экраном.

Система:

1. обрабатывает ответы;
2. формирует внутреннюю типологическую гипотезу;
3. при необходимости запускает уточнение;
4. сопоставляет профиль со средой;
5. моделирует возможные состояния;
6. формирует поведенческий прогноз;
7. проверяет его независимо;
8. удаляет типологический ярлык из внешнего результата.

---

# 29. Статус персонального анализа

Клиент видит только процессуальные статусы:

- приглашение отправлено;
- участие подтверждено;
- 42Q начат;
- 42Q завершён;
- требуется дополнительное уточнение;
- анализ выполняется;
- прогноз готов;
- недостаточно данных.

Клиент не видит внутренний тип.

---

# 30. Выпуск результата

Итог существует в двух формах:

1. живое рабочее пространство;
2. утверждённая версия отчёта.

---

# 31. Организационный прогноз

Для каждого существенного риска показываются:

- затронутая зависимость;
- механизм;
- доказательства;
- противоречия;
- устойчивость вывода;
- временное окно;
- наблюдаемый признак;
- условие опровержения;
- действие.

---

# 32. Индивидуальный прогноз руководителя

Если 42Q завершён, клиент получает:

- роль;
- значение для сделки;
- предполагаемую реакцию на новую среду;
- условия давления;
- риск изменения поведения;
- ранние признаки;
- влияние на исполнение роли;
- влияние на сделку;
- временное окно;
- что наблюдать;
- что может опровергнуть прогноз;
- меры поддержки или контроля.

Типологический ярлык отсутствует.

---

# 33. Краткое представление для инвестиционного комитета

Должно содержать:

- один главный вывод;
- экономическую значимость;
- три–пять ключевых рисков;
- критические неизвестные;
- прогноз;
- необходимые действия до закрытия;
- ограничения.

Любой существенный вывод должен раскрываться до доказательств.

---

# 34. Фиксация прогноза

После утверждения существенные прогнозы фиксируются.

Фиксируются:

- содержание;
- дата;
- версия методологии;
- временное окно;
- наблюдаемые признаки;
- условия опровержения;
- доступные на тот момент доказательства.

Прогноз нельзя незаметно переписать задним числом.

---

# 35. Период после закрытия сделки

До закрытия главный вопрос:

> «Что может произойти?»

После закрытия:

> «Что уже проявилось относительно зафиксированного прогноза?»

---

# 36. Контрольные точки

Рабочая модель должна позволять проверки примерно на:

- 30 день;
- 60 день;

- объяснить переход к платному уровню;
- объяснить роль экономической экспозиции;
