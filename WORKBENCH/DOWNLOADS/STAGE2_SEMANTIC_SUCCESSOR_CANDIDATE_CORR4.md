## F. LANE SEMANTICS

F.1 Semantic equivalence proof. Each DOCUMENTARY_COMPLETE_CANDIDATE row carries: `atoms` (Tree atomic component) → `map` (documentary interpretation = the M's preciseMeaning) → M leaf → `anchor` → coverage = COVERED. The verdict EXACT is mechanically verified (§N, check NOT_EXACT = []) by substituting `map` into `treeExpr` and comparing with `mechExpr`, and semantically attested in §N.2. The substitution test alone is never treated as semantic proof (IV1 RC-VALIDATION/RC-SOURCE correction): every row additionally carries the row-by-row semantic attestation against the cited E9 text.

F.2 Counters. There are two lawful counter types. (i) NEG(M): the bounded negation of a required leaf, established only by COMPETENT_AFFIRMATIVE_ABSENCE at matched scope/time. (ii) A listed counter M applies only when the two Ms decide the same organizational question in incompatible ways — e.g. the same contested issue decided by argument quality vs decided by rank — at matched scope/time; the registry states the incompatibility in each counter entry, and "same hierarchy exists" or "compatible co-occurring mechanism" is never sufficient (F07: M-HIERARCHY-EFFICIENCY and M-POSITION-BY-RESOURCE-HOLD carry no counters). ANY_OF siblings are never counters (alt). Counterevidence against one ANY_OF branch leaves the other branch eligible. A one-episode negative never negates a standing/characteristic proposition outside the negative's actual coverage.

F.3 Target completion function (per target, per side, per claimed scope; single-precedence version, IV2 B6/M5/B4):
```
LEAF RESOLUTION (defined exclusively by §F.5 E-R1–E-R5; no other ordering exists in this contract):
leaf value   := CONFLICTED if E-R1 applies (conflict dominates at leaf level, including positive SUPPORTED
                together with COMPETENT_AFFIRMATIVE_ABSENCE on the same M/object/scope/time)
                else FALSE if E-R2 (NEG established, no positive support)
                else TRUE if E-R3 (≥1 SUPPORTED edge, all components, join satisfied)
                else OPEN (E-R4/E-R5: PARTIAL with missingComponents, GAP, AMBIGUOUS, NOT_DETERMINABLE, or no edges)
NOT_DETERMINABLE leaves (e.g. M-RES-ASYMMETRIC-RETENTION c3 without a lawful comparison basis) stay OPEN-valued
and are marked notDeterminable=true for the target-state rule below.

SUPPORT CONDITIONS (for each edge claimed to support a leaf):
leafTrue(M)  := ∃ edge with edgeState=SUPPORTED for M
                ∧ the edge satisfies the row's join requirement (§F.4 incl. §F.4.1 sameness) for relational leaves
                ∧ sourceQualityState=COMPETENT for the M's proposition (§G)
                ∧ scopeBridgeState∈{NOT_REQUIRED,BRIDGED} for claimed scope
                ∧ temporalState∈{PRE_T0_CONTINUITY_NOT_REQUIRED,PRE_T0_CONTINUITY_BRIDGED}
                ∧ formalOperativeState satisfies row formOp (FO-OP / FO-PRES)
                ∧ planCurrentState=CURRENT
                ∧ charGate satisfied (§K profile; EXCEPTIONAL/EXPERIMENTAL/NOT_ADOPTED always block)
leafNeg(M)   := NEG(M) established by COMPETENT_AFFIRMATIVE_ABSENCE, or a listed incompatible counter M leafTrue for same question

EXPRESSION EVALUATION (order-invariant quantifiers):
eval(ALL_OF) := any child FALSE → FALSE   (a definitely-false conjunct determines the conjunction)
                else any child CONFLICTED → CONFLICTED
                else all children TRUE → TRUE
                else OPEN
eval(ANY_OF) := any child TRUE → TRUE     (a definitely-true disjunct determines the disjunction)
                else any child CONFLICTED → CONFLICTED
                else all children FALSE → FALSE
                else OPEN
A leaf is "needed for the result" iff, given the other leaves' values, changing that leaf's value alone could
change the expression's value; the quantifier order above makes this mechanical and identical in §F.3 and §F.5.

TARGET STATE:
targetState  := UNOBSERVABLE rows → TARGET_UNOBSERVABLE
                eval=CONFLICTED → TARGET_CONFLICT
                eval=TRUE → TARGET_SUPPORTED      [subject to srcDiv below]
                eval=FALSE → TARGET_CONTRADICTED
                eval=OPEN and some needed leaf notDeterminable → TARGET_NOT_DETERMINABLE
                eval=OPEN otherwise → TARGET_NOT_ESTABLISHED_WITHIN_BOUND
```
srcDiv EXECUTION (IV2 M5): for targets declaring `srcDiv` (TT-SFPSFJ-DOC), TARGET_SUPPORTED is emitted ONLY if the supporting edges of the pattern leaves span ≥2 distinct qualifying source classes (§I sourceClass; repackaged duplicates of one underlying document count once; class list in the target row). If the Boolean eval is TRUE but srcDiv fails, the target state is TARGET_NOT_ESTABLISHED_WITHIN_BOUND (named failure state; never FALSE, never TARGET_SUPPORTED).
PRES-LANE NON-CONSUMABILITY (IV2 B4): targets carrying `lane: PRES_EVIDENCE_ONLY` (TT-NFNT-PH-PR) emit their state as presentation evidence only; §I records presentationLaneOnly = YES on every such edge and derived state. HEDC and any downstream consumer may NEVER read that state as support for genuineness, operation, belief or the full canonical property from which the lane was split. This is an execution control, not a note.
There are no scores, counts, weights or thresholds. Prohibition rules PR-* are applied as blocking checks: an edge whose only basis is a listed prohibited criterion is NON_DISCRIMINATING and cannot be SUPPORTED; the block is per-proposition (a forbidden Environment classifier does not make its narrower factual/presentation observation NON_ANALYTICAL). No hidden completion is allowed (C34 §7.4). PRES-lane completion (FO-PRES rows) never upgrades to operative, authentic, voluntary, inner-motive or genuineness claims.

F.4 Relational join rule (load-bearing; IV1 F08). For every M or TT whose proposition is multi-component or relational, completion requires a relational witness: all component edges must be bound to one relationInstanceId referencing the exact organizational object the proposition is about — organizationalObjectRef ∈ {organizational process, decision, program, system, resource flow, relationship, belief system, participation system, hierarchy, enforcement regime, operating structure, expenditure domain, or the other exact object named by the proposition}. Rows declare this through the `join` key: REL-WITNESS(object). Rules:
J-R1 Mere same company, same side, same year, or same corporate group is NEVER sufficient for a relational proposition.
J-R2 Each component edge names the relationInstanceId it supplies; components supplied by edges bound to different relationInstances do not compose.
J-R3 The relationInstanceId references the organizational object via organizationalObjectRef (and decisionRef / resourceFlowRef / participationSystemRef / beliefSystemRef as applicable) — reference fields only; factual truth stays in Stage 1 (§I).
J-R4 One fact may supply components of several Ms inside the same relationInstance (MULTI_ENTAILMENT per §F.5); it may not silently bridge two different relationInstances.
J-R5 TT-composite rows (e.g. TT-SFPSFJ-DOC) require one shared relationInstanceId across all component leaves, plus any row-specific extra conditions (srcDiv).
J-R6 If component edges cannot be lawfully bound to one relationInstance, the leaf is OPEN (the relation is NOT_ESTABLISHED_WITHIN_BOUND), never FALSE.

F.4.1 DOCUMENTARY LINKAGE TEST (sameness of a relationInstance; IV2 B5 — load-bearing).
A relationInstance's sameness is established ONLY by affirmative documentary linkage evidence, recorded per binding as linkageEvidence{class, identifier} in §I. Coder assertion of an identifier, topical similarity, or shared company/side/year is NEVER sameness evidence.
Lawful linkage classes (any one suffices, recorded with its identifier):
- L-1 DIRECT CROSS-REFERENCE: one record explicitly references the other record, or both records reference the same unique identifier of the organizational object (decision ID/number, program name, contract or transaction number, filing accession, policy reference).
- L-2 SHARED NAMED ORGANIZATIONAL OBJECT IN OPERATIVE ROLE: both records name the same decision/process/program/system/belief system/participation system/hierarchy/enforcement regime/resource flow/operating structure, AND at least one of the two records shows that object in an operative role connecting the facts (e.g. the decision is recorded as taken within the named program; the transfer is recorded under the named system).
- L-3 SHARED CONTRACTUAL/TRANSACTION OBJECT: both records concern the same contract, transaction, payment flow or asset, with an identifier present in the records.
- L-4 TRANSACTION/FLOW IDENTIFIER: the same transaction or flow identifier appears in both records.
- L-5 EXPLICITLY LINKED GOVERNANCE RECORD: minutes/approvals/escalations/sanctions that reference the same named decision, program or system (governance chain records).
- L-6 ISSUER OPERATIVE BINDING RECORD: the issuer's own operative record binds the facts to one named object (e.g. an organizational record listing both facts under one named system or program).
NOT sufficient (L-N): same company, same side, same year, same sector; topical similarity; same persons appearing in both records without an operative-object link; coder judgment; inference from similarity of subject matter; absence of a disproof.
AMBIGUITY: if the records could equally refer to two distinct objects (name collision without a disambiguating identifier), the linkage is LINKAGE_AMBIGUOUS → no join.
UNRESOLVED: without a lawful L-1..L-6 record, sameness is NOT established → the relational leaf is OPEN (NOT_ESTABLISHED_WITHIN_BOUND), never FALSE, and the facts are never composed into one relationInstance. Coders record the linkage class + identifier or record NO_LAWFUL_LINKAGE; they never create relations without such evidence. Two coders can reproduce the decision from the same records because the class and identifier are inspectable source content, not coder construction.

F.5 Closed state resolution (single precedence with §F.3; IV1 F08, IV2 B6).
MULTI-EDGE RESOLUTION (before Boolean evaluation) — for the same exact M / organizational object / scope / time, combine all edges deterministically:
E-R1 Any CONFLICT-inducing edge pair at matched scope/time — incompatible competent propositions, or positive SUPPORTED together with COMPETENT_AFFIRMATIVE_ABSENCE NEG — makes the leaf CONFLICTED (conflict dominates at leaf level; never resolved by vote, majority or evidence count; never FALSE, never silent OPEN). This E-R1..E-R5 sequence is THE single normative leaf-resolution rule of this contract (IV2 B6): §F.3's leaf value is defined exclusively by it, so support + competent affirmative absence yields exactly one result everywhere — CONFLICTED → TARGET_CONFLICT.
E-R2 Else if NEG(M) is established by COMPETENT_AFFIRMATIVE_ABSENCE and no positive SUPPORT exists → FALSE.
E-R3 Else if ≥1 edge is SUPPORTED (all components, join satisfied) → TRUE.
E-R4 Else if edges are PARTIAL → OPEN with missingComponents listed.
E-R5 Else → OPEN (GAP / AMBIGUOUS / NOT_DETERMINABLE / no edges).

MULTI_ENTAILMENT vs AMBIGUOUS_INTERPRETATION:
E-R6 MULTI_ENTAILMENT: one fact independently entails ≥2 Ms whose propositions are jointly satisfiable (the registry declares no incompatibility between them). Each M receives its own edge and is fully evaluated; nothing is downgraded; this is not ambiguity.
E-R7 AMBIGUOUS_INTERPRETATION: one fact satisfies components of ≥2 candidate Ms that the registry declares mutually incompatible as descriptions of the same fact instance (each alone would fit; the fact cannot entail both at the same organizational question/object/scope/time), and the fact text does not resolve which applies. The coder records ambiguity{competing M-ids}; edgeState = AMBIGUOUS for all competing Ms; AMBIGUOUS edges never establish (leaf OPEN) and never negate.
E-R8 Declared incompatible pairs (registry-level, for E-R7): M-ADJ-ARGUMENT-QUALITY ↔ M-AUTH-TOPDOWN-EXPLICIT; M-ADJ-TEST-RESULT ↔ M-AUTH-TOPDOWN-EXPLICIT — incompatible only as deciding bases of the SAME contested issue at matched scope/time. Any new pair requires a registry update through the schema-review route (§M); coders never declare incompatibilities ad hoc.

BOOLEAN PRECEDENCE (closed; the four IV1 cases):
E-R9 ANY_OF(A,B): A TRUE, B CONFLICTED → TRUE (B not needed). ANY_OF(A,B): A FALSE, B OPEN → OPEN → TARGET_NOT_ESTABLISHED_WITHIN_BOUND. ALL_OF(A,B): A FALSE, B CONFLICTED → FALSE (A alone determines) → TARGET_CONTRADICTED. ALL_OF(A,B): A TRUE, B CONFLICTED → CONFLICTED → TARGET_CONFLICT.
E-R10 No coder discretion remains around "conflict on a leaf needed for the result": neededness is mechanical (§F.3).

## G. SOURCE-COMPETENCE RULES (proposition-level; A/B; C34 §5.5, §12; ACQ VR-2; IV1 F10)
G-1 An issuer statement is competent for "issuer stated X" (and for PRES objects whose content is the stated frame, per FO-PRES). It is competent for an OP mechanism only with corroboration by evidence independent of the self-description. A self-adverse admission may be probative and is admissible, but it does NOT automatically waive contradiction/corroboration discipline: where the proposition claims actual behavior, scope, recurrence or consequence, C34 §12 corroboration law still applies, and an unresolved contradiction at matched scope/time blocks the edge regardless of the admission.
G-2 An org chart, bylaws or titles are competent for the formal locus → FORMAL_ONLY. They never establish OP by themselves (DE-4).
G-3 A policy or rule text is competent for FORMAL_ONLY. It is OPERATIVE only with ≥1 governed decision, or a competent record of routine application (C34 §8).
G-4 Marketing or engagement material is competent for PRES objects only. It is never competent for desire-activation, voluntariness, authenticity, genuineness or operative control.
G-5 A contract or compensation plan is competent for terms (M-PARTICIPATION-ARCHITECTURE-CONTROL c2 as FORMAL). Operative control needs an applied instance.
G-6 A contemporaneous third-party record is competent only for propositions its actual basis of knowledge supports: direct observation/reporting of a recorded event → competent for the event as reported. It is NOT competent, by default, for an internal deciding basis, motive, recurrence beyond what it documents, functional/causal relations, or governing status — unless the record itself evidences those (e.g. it shows the deciding basis). Competence is decided per exact proposition against: access/basis of knowledge; direct observation; whether an internal decision basis, recurrence, functional relation or causality is claimed; and contradiction/corroboration where required. Stage-1 factual certification establishes the fact's truth, not automatic competence for a stronger analytical mechanism.
G-7 Nominal compensation data is not competent by itself for M-RES-ASYMMETRIC-RETENTION c3 (E9/10 §8); the commensurability rule in that M (IV2 M3) defines the lawful comparison bases (source-provided common unit, or a competent record that itself performs and states/arithmetically entails the comparison) and the mandatory abstention: heterogeneous channels without a lawful basis → NOT_DETERMINABLE. Conclusion-only statements without a stated comparison basis are insufficient for c3.
G-8 No source is competent for inner states (authenticity, lived meaning, motive, psychological capacity, genuineness as an inner quality). Those atoms are UNOBS.
G-9 A plural or generic statement without scope stays at observedScope = unspecified, which fails closed below the claimed scope (C34 §9/§10): it cannot be silently assigned team/unit scope either; unresolved scope → UNRESOLVED_FAIL_CLOSED.
